## Why two paths rather than one

`.git/hooks/` is not version-controlled — a hook installed there survives
nothing and is invisible to review. So the hook's **source** lives at
`scripts/surgery/pre-commit.sh`, tracked and reviewable, and is installed into
`.git/hooks/pre-commit`, which is where git will actually run it. The tracked
copy is the artifact; the installed copy is the effect.

## What you are buying, stated honestly

Accident-defense. Nothing more. `.git/hooks/` is machine-local, does not
survive a clone, and is shell-deletable — I probed that: deleting a git hook is
ALLOW for every role. Your own ruling already labelled it this way and the
hook's header will say so.

It catches the case where a session modifies a tracked `CAMPAIGN/` artifact by
accident, and it gates the layer that actually matters — a write only enters
the **record** through a commit. It stops nothing that is trying.
