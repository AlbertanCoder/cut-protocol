## INCISIONS — the repair, and only the repair

**I1 — Cookie auth in `api()`.** It sends `authorization: Bearer ${token}`.
`requireAuth` in `backend/src/lib/auth.js` reads the session **exclusively**
from the httpOnly cookie `cutprotocol_session`; no bearer path exists anywhere
in the app. Give `api()` a cookie jar that captures `set-cookie` on the sign-in
response and replays it on every subsequent call.

**I2 — Mint the account, then sign in through the real route.**
`POST /api/auth/register` is gated — it permits registration only on a
zero-user install or from a caller already holding a live session — and it
returns `{ id, email, role }` with the session in a cookie, no token in the
body. So the current `reg.json.token || reg.json.accessToken` extraction throws
even when registration succeeds.
Create the witness account directly via Prisma (`hashPassword`, role `user`),
then authenticate through the **real login route** so the cookie is issued by
the same code path a user gets. Do not add a bearer path to the app; do not
weaken the registration gate. The app is not on your manifest and must not be
touched at all.

**I3 — Idempotent, hoisted `shutdown()`.** The failure path currently exits
**127** with a libuv assertion, because `main().catch()` disconnects Prisma
while the registered `process.on('exit', shutdown)` handler kills the spawned
server. A crashed witness and a cap-breached witness must never be
indistinguishable by exit code. Make `shutdown()` safe to call twice and hoist
it so both paths use the same one.

**I4 — Leave the owner's data alone.** The pre-flight dev-DB refusals and the
backup step already work and are not to be modified. The witness account is
dedicated; nothing else in `dev.db` may be mutated.
