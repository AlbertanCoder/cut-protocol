# G7b — PLACEHOLDER is one of several silent skips, and the others take whole files

Builder · authored 2026-07-28 19:47 MDT (2026-07-29T01:47Z) · HEAD `02cc593`
Read-only. Nothing edited outside this file. First artifact under C2 Rule 2.

Extends G7. VERDICT M0.2.3 measured line-level suppression by `PLACEHOLDER` and
found 8 suppressed against 1 reported. That is correct and it is not the whole
surface: `PLACEHOLDER` decides whether the rules run **on a line**. Three other
checks decide whether a **file is opened at all**, and they are quieter, because
a skipped line at least had its file read.

## What the scanner never examines

    node, replicating scanFile's own gates over `git ls-files`

    tracked files      : 640
    actually examined  : 598
    SKIPPED [self]      1   scripts/scanSecrets.mjs
    SKIPPED [binaryExt] 39  .ico / .png assets
    SKIPPED [nulByte]   2   backend/scripts/qc/fuzz.mjs
                            backend/tests/librarySync.test.js
    MAX_BYTES = 2000000

**OBSERVED.** 42 of 640 tracked files are never opened for rules. The image
assets and the scanner's own regex-laden source are deliberate and correct.

## The one that matters: two source files are exempt

`scanFile()` reads the file and then:

    if (buf.includes(0)) return; // a NUL byte marks a binary file — skip it

`backend/scripts/qc/fuzz.mjs` and `backend/tests/librarySync.test.js` are
ordinary tracked JavaScript — 16 KB / 277 lines and 33 KB / 632 lines — and
**neither is ever scanned for secrets.** Each contains exactly **one** NUL byte,
almost certainly a deliberate fixture (a fuzz corpus, a unicode edge case).

The property to notice is not that these two files are suspicious. It is that
**one zero byte anywhere in a file exempts the entire file, silently.** Not
flagged-and-skipped — never read for rules. There is no output, no count, no
line in the report saying 42 files were passed over.

Scale of the two effects, from this repo:

| silent skip | granularity | count here |
|---|---|---|
| `PLACEHOLDER` | one line | 8 suppressed of 9 matches |
| `buf.includes(0)` | **entire file** | 2 source files, 909 lines |
| `BINARY_EXT` | entire file | 39 (deliberate) |
| `MAX_BYTES` | entire file | 0 today |

## Is anything hiding? No — measured, to the standard the architect set

Rules applied to both exempt files with the NUL gate removed:

    backend/scripts/qc/fuzz.mjs         bytes=16053  NUL=1  lines=277  rule_hits=0
    backend/tests/librarySync.test.js   bytes=33354  NUL=1  lines=632  rule_hits=0

**OBSERVED. Zero rule hits in either.** Nothing is hiding behind the NUL gate
today, exactly as nothing was hiding behind `PLACEHOLDER`. The vector is real
and unexercised — which is the useful answer, better than "it's fine" and more
actionable than "it's scary."

## Why this belongs with G7 rather than beside it

Both are the same shape: **a cheap heuristic decides whether the careful rules
get to run, and its decision produces no output.** `PLACEHOLDER` guesses
"example text" from prose; `includes(0)` guesses "binary" from a single byte.
Each is defensible in isolation and each fails silently, which is the property
that makes a scanner's green meaningless rather than merely incomplete.

The repo has already written the general form of this lesson down, in
`CLAUDE.md`'s packaging rule: an exclusion heuristic over a directory that
people keep adding files to is structurally unable to stay correct. This is the
same defect wearing a different hat, in the tool that is supposed to be the
last check before a public push.

## Recommendation

Small and specific:

1. **Report the skips.** `scanSecrets` should print `N files not examined
   (binary: X, nul-byte: Y, oversize: Z)` on every run. A scanner that is silent
   about what it declined to look at cannot be audited, and this one currently
   prints only `clean — 598 file(s) scanned` with no hint that 42 were not.
   This is the whole fix for the auditability half and it is a few lines.
2. **Narrow the NUL test** to a prefix sample rather than the whole buffer, or
   require a NUL *density* rather than a single occurrence. A text file with one
   embedded zero is not a binary.
3. Keep `BINARY_EXT` as is — it is an allowlist-shaped rule over file types and
   it is working.

`scripts/` is off my manifest; `guard-edit` refuses it, correctly. All three
need an order or the owner's hand.
