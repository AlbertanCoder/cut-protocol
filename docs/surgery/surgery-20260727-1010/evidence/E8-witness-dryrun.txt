What FAILED:


DEFECT 1 (FATAL, unreachable-by-construction)
---------------------------------------------
witness.js:208 acquires its dedicated account with an UNAUTHENTICATED
  POST /api/auth/register

backend/src/routes/auth.js:72-93 is not an open endpoint, by deliberate design
documented at :62-71. It permits registration only when EITHER
  (a) the install has zero users  — `isFirstRun`, :81-82, or
  (b) the caller already holds a session resolving to a live user — :87-89.

The witness hard-asserts its target is backend/prisma/dev.db (:83-85) and
refuses every other path. That DB is the owner's populated dev database, so
(a) is false. The witness sends no token on the register call, so (b) is false.
403, every time.

This is not flaky and not environmental. The witness can never satisfy either
branch against a populated dev.db, and it refuses to run against anything
else. The instrument as frozen cannot acquire an account on this machine.

The gate is correct and predates the witness. The witness is what is wrong.


DEFECT 2 (SECONDARY, and it corrupts the failure signal)
--------------------------------------------------------
The error path crashed rather than exiting:

  Assertion failed: !(handle->flags & UV_HANDLE_CLOSING), file src\win\async.c, line 76
  EXIT=127

`main().catch()` (:297-305) calls `prisma.$disconnect()` while the
`process.on('exit', shutdown)` handler (:165) kills the spawned server, and
libuv aborts on Windows. The intended exit code on failure is 1 (:304); the
observed code is 127.

This matters beyond tidiness: any harness that keys on the witness's exit code
reads a failed witness as a nonstandard crash code, not as the documented 1.
A cap-breach exit (1, :294) and a crash (127) must not be confusable.

Mitigation observed this run: no listener remained on port 3999 afterwards, so
the child server was reaped despite the abort. That is luck, not contract.
